# التصميم المستهدف لمنظومة الذكاء الاصطناعي

## المبدأ المعماري

يتحول المشروع من خدمة مركزية تستدعي مزوداً واحداً أو احتياطياً وتعيد نصاً، إلى منصة قرار ومحتوى قانوني مكوّنة من طبقات واضحة: بوابة نماذج، طبقة سياق موثوق، وكلاء وظيفيون محدودو الصلاحية، طبقة حواجز تحقق، سير اعتماد بشري، وسجل قياس وتدقيق.

```text
الواجهة والـJobs
   │
   ▼
AI Gateway / Orchestrator
   ├─ تصنيف مخاطر والبيانات
   ├─ اختيار نموذج وفق المهمة والكلفة والمهلة
   ├─ التحكم في المهلات وإعادة المحاولة وقاطع الدائرة
   └─ سجل طلب موحد ومعرف تتبع
   │
   ├────────► Context Builder
   │            ├─ عزل الصلاحيات والملف المسموح
   │            ├─ تنظيف PII وتصغير السياق
   │            └─ RAG قانوني موثق من مصادر معتمدة
   │
   ├────────► وكلاء محددون المهمة
   │            ├─ فرز واستقبال
   │            ├─ تحليل مستند
   │            ├─ مساعد محامٍ وصياغة
   │            ├─ تلخيص اجتماع
   │            └─ تنفيذ/استخراج قرار
   │
   ▼
Validation & Policy Gate
   ├─ JSON Schema صارم
   ├─ تحقق قواعد العمل والحقول والمراجع
   ├─ كشف حقن التعليمات والبيانات الحساسة
   ├─ قياس الثقة وعدم اليقين
   └─ قرار: قبول / مسودة / مراجعة بشرية / رفض
   │
   ▼
Human Review + Audit + Observability
```

## قواعد التشغيل المستهدفة

1. لا يعدل الذكاء الاصطناعي حالة قانونية نهائية، ولا ينشئ التزاماً مالياً، ولا يرسل مستنداً رسمياً خارج النظام، ولا ينفذ عملية حساسة من دون موافقة إنسانية صريحة.
2. أي تحليل قانوني مؤثر يجب أن يحمل حالة أصل المخرج: `ai_verified`, أو `ai_draft`, أو `fallback`, أو `human_approved`، ولا تعرض الواجهة البديل القالبي كتحليل ذكاء اصطناعي ناجح.
3. يجب أن تربط كل نتيجة قانونية قابلة للاعتماد بمصادر/مقاطع معرفة استندت إليها، وإصدار نموذج، وإصدار Prompt، والوقت، وسياسة الإخفاء المطبقة.
4. لا يملك نموذج اللغة اتصالاً مباشراً بقاعدة البيانات أو بوابة الدفع أو البريد أو Zoom. كل فعل يمر عبر أدوات خادمية ضيقة المعلمات وتتحقق من صلاحيات المستخدم وقواعد العمل.
5. يستخدم كل وكيل أقل قدر من البيانات الذي يكفي للمهمة، ويجري حجب أو تمويه رقم الهوية والجوال والبيانات الحساسة قبل إرسالها لمزود خارجي عندما لا تكون مطلوبة.

## تصميم الوكلاء

| الوكيل | المدخلات المسموحة | المخرجات المسموحة | قرار النشر |
|---|---|---|---|
| وكيل الفرز | نوع التذكرة ووصف مختصر وقائمة خدمات | القسم، الأولوية، النية، سبب مختصر، درجة ثقة | يحدّث كاقتراح أو يرسل لموظف عند الثقة المنخفضة |
| وكيل المستندات | ملف مفحوص وسياق محدود | النوع، الملخص، الارتباط، حقائق مقتبسة، درجة ثقة | لا إحالة تلقائية إذا لم تصل الثقة للحد المطلوب |
| وكيل المحادثة | آخر الرسائل المسموحة وحالة الملف | رد خدمة وتعليمات عامة وطلب توضيح | لا رأي قانوني حاسم ولا وعد أو موعد ملزم |
| وكيل الملف القانوني | وقائع محققة ومستندات مختارة وقاعدة معرفة | ملخص، قائمة أدلة، مسائل، أسئلة ناقصة، مراجع | مسودة للمحامي فقط |
| وكيل الصياغة | حقائق معتمدة ومراجع نظامية موثقة وقالب وثيقة | مسودة لائحة/مذكرة مع استشهادات وفراغات للبيانات الناقصة | لا يمكن مشاركتها أو تصديرها قبل الاعتماد |
| وكيل الاجتماعات | نص محضر/تفريغ أو ملخص Zoom موثق | ملخص، قرارات، مهام مقترحة ومالكوها | عرض اقتراحات، ثم اعتماد المهام أو رفضها |

## اختيار النموذج المستهدف

| نوع المهمة | نموذج تشغيل مقترح | نموذج مراجعة/تصعيد مقترح | مبدأ الاختيار |
|---|---|---|---|
| تصنيف وفرز واستخراج حقول | نموذج سريع ومنخفض الكلفة | نموذج أقوى للحالات منخفضة الثقة | مخرجات JSON بسيطة قابلة للقياس |
| PDF وصور ومستندات طويلة | نموذج متعدد الوسائط طويل السياق | نموذج متعدد الوسائط أعلى جودة | معالجة النص والمرفقات في مسار واحد أو بعد OCR موثوق |
| تحليل قانوني أو صياغة حساسة | نموذج قوي في الاستدلال والنص العربي | مراجعة بشرية إلزامية | الجودة والمرجعية أهم من السرعة |
| تقييم داخلي للمخرجات | نموذج حكم منفصل عن نموذج الإنتاج | مراجعة محام لعينة مستمرة | تجنب التقييم الذاتي لنفس النموذج |

## قاعدة المعرفة القانونية (RAG)

تبنى قاعدة معرفة معتمدة ومُؤرشفة، لا تعتمد على ذاكرة النموذج فقط. تتضمن نصوص الأنظمة واللوائح والأدلة الإجرائية والقوالب الداخلية وسياسات المكتب بعد مراجعة قانونية. كل وثيقة تحمل المصدر، تاريخ السريان، الولاية القضائية، النسخة، ونطاق الاستعمال. تتبع عملية الاسترجاع فلاتر إلزامية حسب الاختصاص وتاريخ السريان ونوع القضية، ثم تدفع مقاطع موثقة إلى النموذج. إذا لم توجد مصادر مناسبة، يخرج الوكيل «لا توجد مراجع كافية» بدلاً من اختراع مادة أو رقم نظامي.

## ضبط الجودة والتقييم

تتكون منظومة التقييم من بيانات معيارية مجهّلة يضعها محامون وموظفون، وتغطي الحالات الطبيعية والناقصة والمتناقضة والعدائية. لكل وظيفة معيار نجاح خاص بها: دقة الفرز، اكتمال استخراج المستند، صحة الإسناد للمصدر، سلامة اللغة، وعدم ذكر حقائق غير موجودة. يمنع نشر Prompt أو نموذج جديد قبل اجتياز مجموعة اختبارات ثابتة ومقارنة A/B مع الإصدار السابق.

## المراقبة والتكلفة

يسجل كل طلب: نوع المهمة، معرف ملف مموه، إصدار Prompt، النموذج، المزود، زمن الانتظار، الاستهلاك، حالة fallback، نتيجة التحقق، وقرار المراجع. وتبنى لوحات تبين جودة كل وظيفة، نسبة المراجعة البشرية، نسب رفض المخرجات، الفشل حسب المزود، المهلة، والكلفة لكل ملف/عميل. تستخدم ميزانيات يومية وشهرية وحصص لكل مستخدم وتوقف تلقائي للحالات غير الطبيعية.

## الأمن والخصوصية

تطبق حماية حقن التعليمات على نصوص العملاء والمستندات، ومعالجة المخرجات كبيانات غير موثوقة. تحجب الأوامر الموجودة في المستندات عن التحكم في النظام، ولا يفسر أي نص مرفوع كتعليمات تشغيلية. تمنع مخرجات النموذج من المرور مباشرة إلى HTML أو عمليات حساسة، وتخضع لتعقيم العرض والتحقق من المخطط وقواعد العمل. وتحدد سياسة احتفاظ بمدخلات ومخرجات الذكاء الاصطناعي، ومسار محو، وتشفير، وسجل وصول، وموافقة استخدام واضحة.
